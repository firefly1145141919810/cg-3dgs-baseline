# 从零理解 3D Gaussian Splatting baseline

读完本文，你应该能回答五个问题：输入究竟是什么？三维场景存成什么？它怎样画出一张图片？它怎样从错误中改善？如何证明结果有效？不要求你先会图形学，但需要愿意把“立体照片”的直觉逐步对应到变量与代码。

本阶段不是压缩、不是生成式 AI，也不要求发明新算法。我们先建立标准原版 3DGS，让后续扩展拥有可信的对照。核心实现来自作者的 2023 官方代码；本仓库新增流程和教学工具，不把官方算法算作我们的原创。

## 1 先想象给一张桌子拍一圈照片

你围着桌子拍了几十张照片：左边能看到桌腿，右边能看到杯把，前面能看到杯子图案。现在希望电脑在一个没拍过的位置也能“拍”出合理的照片。这个任务叫新视角合成，英文 novel view synthesis。

它不是把两张照片简单平均，也不是从文字凭空画一张桌子。程序要找到一个能同时解释多张照片的三维表示，再依据新的相机位置重新计算画面。

但照片没有提供所有信息：从未拍到的桌子底面、被杯子挡住的区域仍然不确定。所以不能保证任意角度都正确，更不能把好看的新视角当成毫米级几何重建。

### baseline 到底指什么

baseline 是后续实验的基准系统。例如以后研究压缩，必须比较“未压缩的标准模型”和“我们的压缩模型”，而不是与另一台机器、另一套照片、另一种分辨率的结果比较。

现在要建立的是：固定官方版本＋固定数据处理＋固定训练配置＋固定测试视角＋可追溯结果。这个阶段跑通非常重要，但仅跑 baseline 尚不满足课程要求的实质扩展。

## 2 六个最基础的词

**像素 pixel：** 一张照片由规则排列的小格子组成，每格保存红、绿、蓝三个数。为了计算方便，通常把每个通道缩放到 0 到 1。

**三维坐标：** 用三个数 (x,y,z) 表示位置。坐标数值本身不一定是米；SfM 重建往往只有相对尺度。只要相机和场景使用同一个坐标系统，就能进行投影。

**相机：** 不仅有位置，还有朝向、焦距和图像尺寸。站在同一个位置朝另一个方向拍，画面会完全不同。

**渲染 rendering：** 给定场景和相机，计算它应该看到的图片。它是一种“从三维到二维”的过程。

**优化 optimization：** 改动场景参数，让渲染图更接近真实照片。它不是手工一点点调，而是用误差和导数自动更新。

**训练与测试：** 训练图片提供修改参数的依据；测试图片只用于检查没参与光度训练的视角。把测试照片也拿来更新参数，测到的就不再是同一件事。

## 3 输入不是随便一个照片文件夹

原版 3DGS 需要知道每张照片从哪里拍、朝向哪里、相机焦距是多少，并需要一些初始三维点。对真实场景，通常先用 COLMAP 做 Structure from Motion，简称 SfM：从多张照片的重复特征估计相机姿态和稀疏点云。

把它想成：先找出“这几张照片里的同一窗角”，结合多张观察反推出窗角大概在哪里、相机大概在哪里。稀疏点云只是少量可靠位置，并非已经有完整表面。

我们的第一个数据集由作者预处理，因此第一轮不必自己运行 COLMAP。`sparse/0/cameras.bin` 是内参，`images.bin` 包含相机姿态和文件名，`points3D.bin` 是稀疏点；`images/` 是对应的去畸变照片。

“去畸变”是把镜头弯曲造成的变形校正到针孔相机模型。当前代码只接受 SIMPLE_PINHOLE/PINHOLE 相机，不能把带畸变参数的原始照片直接当成相同输入。

**注意名称：Tanks and Temples 的 `train` 是火车场景，不是“训练集目录”。** 我们会在这个场景内部进一步划分训练照片和测试照片。

## 4 三维点怎样变成图片上的点

先把世界坐标转换为相机坐标。为便于理解，用以下数学约定：

```text
p_camera = R * p_world + t
u = fx * x_camera / z_camera + cx
v = fy * y_camera / z_camera + cy
```

R 是旋转，t 是平移；fx、fy 与焦距有关，cx、cy 是投影中心。u、v 是图片上的位置。相同大小的物体离相机更远，除以更大的 z 后，投影就变小，这就是近大远小。

例如 fx=1000，cx=800，一个点在相机坐标 (1,0,5)，则 u=1000×1/5+800=1000；如果移到 (1,0,10)，则 u=900，离图像中心更近。真正程序会把这些运算写成矩阵，CUDA 还涉及转置和内存布局，不要仅凭数组外观猜行列含义。

相机中心不总是外参中的 t。若世界到相机为 R*p+t，则相机中心为 -R^T*t。把两者混淆会让相机轨迹和投影出错。

## 5 场景为什么用“高斯”表示

普通点云像一堆没有大小的针尖；网格用三角形连接出表面；3DGS 则使用有位置、形状、透明度和颜色规律的三维高斯。

你可以把一个高斯想成一小团彩色雾：中心影响强，越往外影响越弱，它不是边界清楚的实体球。许多这种“雾团”相互配合，能画出表面与细节。

高斯在数学上的影响形状写作：

```text
G(x) = exp(-0.5 * (x-mu)^T * inverse(Sigma) * (x-mu))
```

- mu：雾团中心，三个位置数。
- Sigma：协方差矩阵，用来描述沿不同方向的伸展与方向。
- inverse：矩阵的逆；T：转置；exp：指数函数。

这里只是形状权重，不必当成概率密度积分为 1 的分布；最终可见贡献还会乘 opacity。中心处 G=1，离中心越远 G 越小。

### 每个高斯具体存什么

| 参数 | 直觉 | 原版变量 |
| --- | --- | --- |
| 位置 3 个数 | 放在哪里 | `_xyz` |
| 尺度 3 个数 | 三个方向有多宽 | `_scaling` |
| 旋转 4 个数 | 椭球朝向 | `_rotation` |
| 不透明度 1 个数 | 自身影响有多强 | `_opacity` |
| SH 颜色系数 | 从不同方向看是什么颜色 | `_features_dc`、`_features_rest` |

代码用旋转与正尺度构造协方差：Sigma = R * S * S^T * R^T。这样比直接随便修改九个矩阵元素更容易保持合法形状。四元数用四个数表示三维旋转，但应归一化；它不等于四个欧拉角。

内部保存的并不都是直接能用的物理量：scale=exp(raw_scale)，opacity=sigmoid(raw_opacity)，rotation=normalize(raw_rotation)。前两种转换分别保证尺度为正、透明度在 0 到 1。直接读取 PLY 后把 raw opacity 当成 alpha，会得到错误解释。

SH 最高三阶有 (3+1)^2=16 个基函数，每个颜色通道各一组，所以颜色系数一共 48 个；连同位置、尺度、旋转、opacity，共 59 个可训练标量。文件还可能存储占位法向等字段，因此不能只用 59×4 精确推算整个 PLY 大小，更不能用它推算训练显存。

## 6 为什么颜色不是固定 RGB

金属杯子从不同角度看，高光位置会变化；同一个位置的颜色并不总是相同。原版用 spherical harmonics（球谐函数，SH）表达有限复杂度的方向变化。

把它类比成用几种固定波形拼出一段信号：方向 d 决定各基函数的值，每个高斯学习一组系数，然后加权组合成颜色。

```text
color(d) ≈ sum_k coefficient[k] * basis[k](d)
```

零阶只有常数颜色；更高阶能表示更细的方向变化。训练从零阶开始，每 1000 步增加一阶，最多到三阶，使早期不必同时处理过多自由度。官方具体实现还包含颜色偏移和非负截断，阅读 SH2RGB 与 CUDA 的 computeColorFromSH 可以看到约定。

**这不是完整物理材质。** 学到的颜色已经包含拍摄时的光照影响，不能因为有 SH 就认为可以任意换灯、得到物理正确重光照。三阶 SH 也不保证捕捉非常尖锐的镜面反射。

## 7 Splatting 到底在做什么

Splat 可以理解成“把一团贡献铺到图片上”。给定相机，每个三维高斯投影成一个二维椭圆形影响区域；覆盖的像素按距离中心的远近得到不同权重。

投影一个有体积的形状，比投影中心点复杂。透视投影不是线性的，原版在高斯中心附近用局部线性近似，得到二维协方差。数学上可简写为：

```text
Sigma_2D = J * R_camera * Sigma_3D * R_camera^T * J^T
```

J 是投影函数对三维坐标的导数矩阵（Jacobian，雅可比）。直觉上，它告诉你：中心位置附近向某方向移动一点，图片位置会移动多少。使用它才能把三维的伸展方向转换成二维椭圆的宽窄与方向。

原代码会对二维协方差加小的对角项，形成最低像素足迹，避免高斯过小导致数值或覆盖问题。该处理不等于后来专门提出的完整抗锯齿扩展。

## 8 多个高斯覆盖同一像素时，如何决定颜色

不能直接取最近高斯的颜色，也不能全部平均。先考虑前后遮挡，再按透明度混合。

对某个像素，把候选高斯按深度顺序处理。第 i 个高斯在这个像素上的 alpha 等于自身 opacity 乘二维高斯权重，再施加实现中的限制：

```text
T_1 = 1
contribution_i = T_i * alpha_i * color_i
T_(i+1) = T_i * (1-alpha_i)
final_color = sum_i contribution_i + T_end * background
```

T 是透射率：穿过前面所有高斯后，还剩多少“看到后面”的机会。

例子：前面是红色 (1,0,0)，alpha=0.6；后面是蓝色 (0,0,1)，alpha=0.5；背景黑色。前面贡献 (0.6,0,0)，后面只能利用剩下 0.4，所以贡献 (0,0,0.2)，最终为 (0.6,0,0.2)。剩余透射率为 0.2。若交换前后顺序，结果会变，所以排序不能忽略。

这与第一次作业的普通深度测试不同：透明高斯通常需要多个贡献累积，而不是一个深度值只留下最近表面。公式与体渲染具有联系，但 3DGS 采用投影、排序、混合的高效近似，不是在每条光线上密集采样神经网络。

## 9 为什么能画得快

如果每个像素都检查全部高斯，假设一百万像素、一百万高斯，代价不可接受。官方把屏幕划成 16×16 像素的小块（tile）：

1. 排除明显看不到的高斯。
2. 估算每个投影椭圆涉及哪些 tile。
3. 为高斯涉及的 tile 建立对应记录。
4. 根据 tile 标识和高斯深度进行排序。
5. 每个 tile 在 GPU 上并行处理自己的像素，按顺序混合候选高斯。
6. 当剩余透射率很低时提前停止，跳过微小贡献。

相较于逐像素遍历所有点，这避免了大量无关工作。注意排序主要依赖高斯中心深度，不是所有像素都做精确几何表面排序；某些交叠情况下仍可能出现近似误差、跳变或伪影。

CUDA 是编写 NVIDIA GPU 并行程序的工具。PyTorch 负责张量、优化流程与部分自动求导；自定义 CUDA 扩展负责高效光栅化和相应反向计算。**GPU 画图快，不等于训练本身不要时间。** 每个新场景仍需优化。

## 10 “训练”到底改了什么

这不是训练一个能认识所有房间的大模型。原版 3DGS 对每个场景单独优化高斯参数；没有必须经过的大型 MLP 主干网络。PyTorch 的使用并不意味着一定有深层神经网络。

一轮训练可理解为：

```text
选择一张训练照片及对应相机
从这个相机渲染当前的高斯场景
将渲染图与真实照片比较，得到 loss
反向传播，计算参数改变会如何影响 loss
Adam 根据梯度更新位置、形状、颜色与透明度
在指定时刻增加、拆分或删除高斯
```

梯度是“误差对于参数的变化率”。如果轻微移动某个高斯可以降低误差，更新规则会倾向于往相应方向移动。学习率控制步长：太大可能震荡，太小可能收敛慢。Adam 还保存与过去梯度有关的状态，所以训练内存不止最终模型参数。

默认损失为 0.8×L1 + 0.2×(1−SSIM)。L1 是对应像素通道的绝对差平均；SSIM 比较局部结构、亮度和对比度。不要把这个实现的 1−SSIM 和其他资料中带额外 1/2 系数的 DSSIM 定义混用。

一个 iteration 通常选一张训练相机；30000 步不是看了 30000 次完整数据集，也不是固定看同一张照片。代码会从相机列表随机取出，取完再重置。相机姿态在这版 baseline 中不是待优化参数。

## 11 初始化与增密为什么很重要

### 起点

每个 COLMAP 稀疏点初始化为一个高斯：位置来自稀疏点，基础颜色来自点颜色，初始尺度与邻近点距离相关，初始旋转为单位旋转，opacity 初值约 0.1。初始点不够密，所以不能只靠改变颜色获得全部细节。

### 需要更多表达能力时

程序统计高斯投影中心梯度大小。直觉上，某些区域仍需显著调整，说明当前表示可能不足。这不是直接把“像素误差最大的像素”转成一个新三维点，梯度与像素误差不是同一个量。

- 小高斯但梯度较大：clone，增加一个副本。
- 大高斯且梯度较大：split，拆成较小高斯，以更细的形状覆盖局部细节。
- opacity 太低等情况：prune，删除贡献较弱或满足其他删除条件的高斯。

本次锁定源码的 clone 直接复制参数，之后优化使其分化；split 从当前高斯周围采样新中心、缩小尺度并删除原高斯。讲论文的概念示意时，不要误写成源码每个 clone 都已主动沿梯度移动。

原版还有 opacity reset：周期性压低不透明度，给其他高斯重新调整的机会，之后再优化与裁剪。它不是定时把所有点删掉。

默认从 500 步之后开始按每 100 步尝试增密，在 15000 步之前结束；精确触发条件见 train.py 的 `iteration > densify_from_iter` 与 `< densify_until_iter`。增密和裁剪是离散策略，不是所有步骤都能直接通过一次普通梯度下降得到。

## 12 输出是什么，不是什么

**PLY** 保存高斯参数：位置、SH 系数、透明度内部值、尺度内部值和旋转等。虽然扩展名常用于点云，它不是带三角面的 mesh，也不是普通 RGB 点云。普通点云软件可能只显示高斯中心，而不能重现最终效果。

**checkpoint** 除参数外包含继续优化需要的状态。PLY 可用于查看，不能直接替代训练 checkpoint。旧版本 checkpoint 也不保存全部随机抽样状态，所以“能继续训练”和“完全无缝逐位复现”是两回事。

**渲染 PNG** 是给定相机下的二维结果，方便检查与比较，不是三维模型本身。

**预训练模型** 可以快速演示，但直接下载作者训练好的模型，不能证明我们的训练链路跑通。因此本 baseline 从稀疏点启动，预训练模型不作为验收替代。

## 13 如何知道模型好不好

测试集由原版规则得到：按 image_name 排序，每第 8 个视角作为测试，含索引 0。训练通过 --eval 排除这些照片的光度监督。评测时用这些相机渲染，再与真实照片比较。

| 指标 | 通俗解释 | 方向与限制 |
| --- | --- | --- |
| PSNR | 像素误差转成对数数值 | 越高通常越好；受分辨率、曝光与背景影响 |
| SSIM | 局部结构像不像 | 越高通常越好；不等同于三维正确 |
| LPIPS | 预训练视觉网络认为差多少 | 越低通常越好；依赖网络/实现版本 |
| 推理毫秒 | 画一张图花多久 | 要说明是否含读盘、保存与 GUI |
| 高斯数量/PLY体积 | 表示有多大 | 不等于训练显存，也不保证严格对应速度 |

PSNR 对归一化到 [0,1] 的图像可写成 -10 log10(MSE)。例如 MSE=0.01 时为20 dB；MSE=0.001 时为30 dB。这里只是公式例子，**不是本项目实测结果**。评测代码应按相同实现逐视角统计再平均，不能随意替换成全数据 MSE 后取一次对数。

LPIPS 会用预训练网络，但它只用于评价，不表示 3DGS 主模型就是这个网络。首次计算可能需要联网下载权重。

必须同时看图片和数字：指标平均好看可能掩盖少数严重失败视角；随便挑一张最好看的照片也不代表整体质量。建议固定近景、远景、细结构和失败视角，展示 GT/预测并列图。

## 14 为什么现在不直接与论文分数画等号

论文结果关联数据预处理、分辨率、训练时长、代码版本、GPU 和评测实现。我们的目标先是复现算法流程并建立项目内可比较的基线，不是未经核对就宣称达到表格中的数字。

本仓库使用较新的可安装 Python/PyTorch 配置，但核心算法锁定早期官方版本。GPU 并行加法等操作也可能存在非确定性。合理做法是保存环境与协议，报告真实结果，然后分析差异；不是为了追论文数值偷偷调整测试集。

截图渲染保存 PNG 的速度包含编码与磁盘 I/O，不能当作纯实时渲染 FPS。我们独立提供 CUDA events 计时；这个计时也只代表官方 Python 渲染入口，不等同于论文中优化过的 SIBR 查看器。

| 如何从 Python 调用 CUDA 渲染器 | `gaussian_renderer/__init__.py` 的 render |
| clone/split/prune 怎么做 | GaussianModel 的 densify_and_prune 等函数 |
| 屏幕椭圆、alpha混合怎么计算 | `submodules/diff-gaussian-rasterization/cuda_rasterizer/forward.cu` |
| 如何求导 | 同目录的 backward.cu |
| 如何导出测试图 | `render.py` |
| 如何统计 PSNR/SSIM/LPIPS | `metrics.py` |

以上路径均相对 `vendor/gaussian-splatting`。我们自己写的 scripts/run.py 不替换上述算法，它只是准确组织命令、检查数据、保存记录、防止混用结果。

## 16 看一遍完整的流程

```text
多张照片
  → SfM 得到相机与稀疏点（首个数据集已经提供）
  → 按固定规则分出训练视角、测试视角
  → 用稀疏点初始化彩色高斯
  → 训练视角渲染 → 对比真实图 → 求梯度 → 更新参数
                        ↑                 ↓
                        └── clone/split/prune 后继续 ──┘
  → 保存最终高斯模型
  → 从测试相机渲染（不更新模型）
  → 统计画质、大小、速度并留存实验记录
```

这个系统完成的是场景表示和新视角合成。它不会自动理解“这是桌子”、不自带物理碰撞、不自动生成标准网格，也不保证随意改变光照的结果。明确这些边界，才能决定后续扩展到底改哪个环节。

## 17 你们两个人至少应该会回答的问题

1. 为什么仅有照片还不够？因为投影需要相机姿态和内参，稀疏点提供合理起点。
2. 为什么高斯比单独一个点更好？它有可优化大小、方向与连续像素影响。
3. SH 做什么？近似颜色随观察方向的变化，不是完整光照仿真。
4. 为什么不能直接把所有高斯颜色相加？前后遮挡与透明度会影响可见贡献。
5. 每一步训练更新哪些东西？高斯位置、形状、颜色和 opacity，当前 baseline 不更新相机。
6. 增密是不是把照片像素复制成三维点？不是，它根据高斯相关梯度与尺度做离散调整。
7. 是否使用测试照片训练？不使用其光度损失；预提供 SfM 可能基于完整图像集，需准确说明。
8. 为什么不能用 1k 冒烟分数当正式 baseline？分辨率和训练预算不同，很多阶段还未充分完成。
9. Gaussian 数量减少是否一定加速？不一定，屏幕覆盖、排序与带宽等也影响开销。
10. 我们当前的原创贡献是什么？实验封装与学习工具；算法扩展还没开始，不应虚报。

## 18 推荐学习顺序与资料

一个容易忽略的论文与代码差异：论文实验部分描述了从四分之一分辨率开始、每250步提高分辨率的安排；本项目锁定的2023官方源码没有实现该逐步分辨率调度，而是按加载的图像分辨率训练。因此这里复现的是固定官方代码的 baseline，不应声称逐字实现论文所有细节。类似地，前文已经说明 clone 操作在论文描述与这份代码中的差异。

第一遍：读本教程1–3、5、7–8、10–13节，用自己的话讲输入到输出。第二遍：结合论文第3–6节与批注理解公式。第三遍：沿上面的源码表阅读训练循环和 GaussianModel，最后才深入 CUDA 前向与反向。

- 原论文与作者页面：https://repo-sam.inria.fr/fungraph/3d-gaussian-splatting/
- 官方代码固定提交：https://github.com/graphdeco-inria/gaussian-splatting/tree/2eee0e26d2d5fd00ec462df47752223952f6bf4e

遇到不理解的公式，先问它在流程中解决什么问题，再看每个符号。比如协方差回答“这团高斯长什么形状”，投影回答“它落到屏幕哪里”，alpha混合回答“多个贡献怎样合成”，梯度回答“参数朝哪里改能减少误差”。这样比先背缩写更容易形成完整理解。
