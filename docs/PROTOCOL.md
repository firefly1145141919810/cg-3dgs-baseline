# Baseline 实验协议与验收

## 固定什么，为什么固定

baseline 是以后扩展的尺子，不是随手跑出的某张好看图片。当前算法是官方 2023 提交 `2eee0e26d2d5fd00ec462df47752223952f6bf4e`，核心源码不改动。算法锁定不意味着与论文原始执行环境完全一致，因此不能承诺逐位一致或直接复现论文表格。

| 项目 | 正式配置 |
| --- | --- |
| 场景 | 作者预处理 T&T train、truck，两场景均已完成 |
| 初始化 | COLMAP 稀疏点，及其颜色与相机标定 |
| 拆分 | 按上游 image_name 排序，第 0、8、16…张留作测试 |
| 训练步数 | 30000；每步一张训练相机，不是一个 epoch |
| 分辨率 | -1，即上游默认自动缩放至最大宽度 1600 |
| SH 最大阶数 | 3 |
| 颜色损失 | 0.8 L1 + 0.2 (1-SSIM) |
| 增密 | 保持原版阈值、clone/split、prune、opacity reset |
| 种子 | 原版 safe_state 内固定 0 |
| 未启用 | 后续抗锯齿、曝光补偿、深度监督、压缩和其他扩展 |

SfM 相机和稀疏点按作者提供的完整预处理数据使用。测试图像不进入 3DGS 的光度损失；这并不意味着测试图像从未参与数据集的 SfM 标定。应准确描述该评测惯例，不能宣称严格训练图像独立建图。

## 云端验收清单

1. `doctor.py` 无 errors，两个 CUDA 扩展可以导入。
2. `dataset.py` 能读取每张已注册图片，确认相机为 PINHOLE/SIMPLE_PINHOLE。
3. 1k 冒烟实验三个阶段成功，检查至少三张预测图不是全黑/全白/错位。
4. 30k 实验完成，最终 PLY 和 checkpoint 存在；manifest、数据哈希和日志完整。
5. 测试图数量与 dataset.json 的 test 一致，预测与 GT 索引配对正确。
6. results.json 有 finite 的 PSNR/SSIM/LPIPS；检查 per_view.json 中异常视角。
7. 至少展示近景、远景、细结构三类视角的 GT/预测/误差图，不能只挑最佳图。
8. 如果报告速度，单独运行 benchmark，注明 GPU、分辨率、计时范围及预热次数。
9. 导出小型结果到 results，完整输出归档到独立存储；核对归档哈希。

目前两场景baseline、压缩扩展及独立重复计时均已云端完成。验收证据与范围见STATUS及实验文档；本清单不代表所有归档、演示和提交动作均已完成。

## 公平比较的规则

后续扩展与 baseline 应使用相同场景、同一相机划分、图像预处理、背景、评测网络与分辨率。想比较同等训练时间，就不能只固定迭代数；想比较同等迭代数，就同时记录实际时间。修改一个变量，其余保持一致，并写明非确定性来源。

测试集用于最终报告，不用于反复挑参数。后续需要调扩展超参数时，应从训练视角中再划验证集，或事先固定策略；不能看测试分数选出最好的一版然后宣称无偏提升。

PSNR 越高、SSIM 越高、LPIPS 越低通常越好。指标不是几何真值，也不保证自由飞行路径都好看。速度与质量需要一起看，较小图片和较少高斯一般能减少某些开销，但不能把不同条件下的 FPS 直接比较。

## 输出含义与安全

- `point_cloud.ply`：用于渲染的高斯参数，不是三角网格；普通点云查看器不能正确展示 SH 与透明混合。
- `.pth`：含优化状态，可恢复训练；只加载自己的可信文件。PyTorch 旧版反序列化可能执行代码。
- `cfg_args`：原版用 eval 读取的参数文件，只使用自己生成的可信运行目录。
- `benchmark.json`：单张 GPU 上的 Python 渲染路径计时，不是完整 GUI 帧率。Torch allocator 显存不包含所有进程与驱动分配。
- `stage_history.jsonl`：墙钟时间含启动、评测和保存，不应直接当成每步 GPU 时间。
